# P1 實作與驗收紀錄

日期：2026-09-10。狀態：本機實作，尚未部署。AI API：未使用、未新增付費服務。

## 這一版的流程

首頁「幫我找適合的旅行」→ `/find-trip` 選擇服務 → 填需求 → 比較最多三個版本與各自團期 → 確認摘要 → 沿用原有詢問保存、通知與後台查詢。

- 四種入口：跟團、自組客製、機票／機加酒／包車、尚未決定／其他需求。
- 可略過未決定的條件，不需先登入或留下電話。機票服務增加回程與行李欄位；客製增加住宿／交通欄位。
- 已知不符的必要條件會排除；必要資料未知的版本放在獨立、預設收合的待確認區，不算符合條件。人數與文字需求只交給顧問，不宣稱自動判斷是否適合。
- 只使用有文件的已公布版本、有效未來團期與版本適用日期。不使用客戶歷史出團紀錄作為商品。
- 每人預算只配對業務設定為「每人」、且可確認明確金額的價格。起價、區間價、每房、整團、未知基準交給顧問確認。依出發日排序，不跨基準按價格排名。
- 無結果時說明排除原因，保留原需求。商品來源載入失敗時明示，停用配對，不使用快取舊商品冒充最新資料。
- 比較航空、航班、天數、住宿、所選日期、價格基準及文件確認日期。沒有文件確認日期時顯示未提供；不以網頁載入時間取代。
- 摘要包含服務、條件、原始補充、版本識別、所選日期、價格、團期備註及待確認項目，與客人最後補充一起保存。後台可用既有搜尋找到「官網旅行需求入口」。
- 返回比較時保留已填聯絡資料；重新載入或關閉分頁不保留草稿。未將聯絡資料寫入網址或 localStorage。
- 送出期間防止連按；相同提交識別與相同內容使用同一物件鍵，以條件新增避免網路重試覆寫通知狀態。修改內容視為另一筆需求。
- 保存失敗顯示錯誤；保存成功才顯示收件成功，通知沿用既有背景重試。通知較長時提示後台查看，完整摘要仍保存在後台。

## 業務上線前操作

1. 平常維護原有行程、團期、價格與航空版本即可。「進階配對設定」已改為收合的選填項目，通常不需逐一設定。
2. 舊版本不必先補齊標籤。明確的價格單位與出發機場文字可自動讀取；缺少必要資料時放進獨立待確認區。選填覆寫可修正例外；文字單位和覆寫矛盾時不判定符合預算。
3. 確認第一批可售團期、每人價格與版本關係，走一次需求入口、比較與詢問。公布團期不表示保證有位，最終報價仍由業務確認。
4. 正式環境做一筆可識別的驗收詢問，核對 Bucket 保存、後台全文、LINE／Webhook 通知及失敗重試。本機測試沒有發送真實業務通知。
5. 取得實際案例公開同意後補服務案例；將 `/find-trip` 分享到既有 LINE／社群。這些對外發布尚未執行。

## 量測與尚未完成的營運工作

已加入 `/api/finder-events`，只接受固定事件：view、start、complete、no_results、contact_saved。應用程式只記錄事件與時間，不記錄客人欄位、網址參數或識別碼；事件失敗不阻止表單。

目前寫入伺服器日誌，view 是需求頁載入，不是首頁入口曝光；重新載入或重試可能重複計數。這不是獨立訪客數、有效詢問數或成交數。尚未建立分析儀表板，正式日誌保留期間待確認。

仍需安排：首頁入口曝光量測、渠道來源歸因、業務有效詢問／成交標記、經同意的案例、正式環境驗收與四週試行。原 TODO P1-12～P1-16 不算完成；P0 的正式版本、服務與商品資料仍需業務確認。

## 出團表程式盤點

使用者提供的兩份附件內容相同。程式使用 Supabase 密碼登入、登入狀態監聽、資料表讀寫、Storage 上傳與限時簽署連結。這能作為 P2 盤點的起點，但僅靠前端程式不能證明資料表 RLS、Bucket 權限或正式帳務語意已正確設定。

P1 沒有複製附件、憑證或客戶資料到官網，沒有修改出團系統，沒有增加跨系統權限。未來 P2 仍須獨立確認資料授權與客戶訂單存取控制。

## 驗證範圍

- 新增規則、摘要、資料正規化與原子保存測試；包含 20 個配對情境及特殊欄位、錯誤路徑。
- Chrome 本機操作確認：無結果→摘要、選擇不同團期、三版本上限、比較表資料、鍵盤返回、聯絡資料保留。
- 首版曾檢查 390px 與 320px 比較表。2026-09-16 改用逐步問答與收藏卡，已不使用比較表。
- 多版本 UI 使用暫時的本機示意資料，檢查後移除，沒有發布成真實商品。
- 正式 Bucket 的條件寫入與通知實際效果仍待上線驗收；單元測試使用模擬儲存，不等同正式外部服務驗證。

最終驗證：52 個單元測試通過（原有 25＋新增 27），lint 與正式版 build 通過。

## 2026-09-16：活潑卡片與低維護改版

- 五步問答：旅行方式 → 目的地 → 出發安排 → 預算 → 同行與心願。保留上一題、可不填的未知條件、鍵盤操作與聯絡草稿。
- 彩色服務卡、預算快捷按鈕、進度提示與 CSS 輕量進場效果；遵循系統減少動畫偏好，沒有新增動畫套件。
- 行程與三版本比較改為收藏卡，可分別選團期與移除，手機直向排列；全流程不使用表格。
- 日期、價格、地區、航空、天數與文件沿用原有內容。出發機場僅從航班／版本摘要中明確的「桃園出發」或「出發機場：桃園」等格式讀取，不從目的地、往返航線或景點名稱猜測。
- 每一團期的實際價格若已寫明「／人」「／房」「整團」，自動讀取基準。不把數字價格默認為每人；起價不能證明最終價格低於上限。
- 未標服務類型的版本可在跟團需求的待確認區被發現；不宣稱是已確認跟團商品，不將它自動推薦為客製或單項服務。明確已標其他服務、機場不符、日期不符或已知超預算的商品不會進待確認區。
- 手動欄位保留作為進階選填覆寫，原本已填的資料不會被刪掉。文件確認日未填時不要求補填；不把上傳日期偽裝成內容已驗證。
- 不讀取 PDF 內容、不使用 AI API、不新增付費依賴。少步行、長輩適合度、購物安排與團位等不從標題臆測。

維護重點：商品與團期原始資料仍需正常更新；這次取消的是為需求入口重複標記資料的負擔，不是讓商品資訊永遠不必維護。
2026-09-16 驗證：58 個單元測試、lint、build 通過。Chrome 已驗證五步問答、手機無溢出、無結果摘要、已知／待確認版本分流、三卡上限及團期同步；暫時示意頁已移除。未向正式儲存或業務通知送出測試資料。

## 2026-09-16：首頁入口與關鍵字搜尋

首頁需求入口改為獨立底色主題卡、大按鈕與旅行票卡裝飾，手機保留主操作並隱藏裝飾。上、下兩組搜尋共用關鍵字欄位，以 q 網址參數保存；搜尋、分類、更多行程均保留條件，完成搜尋後兩欄同步，支援清除。

搜尋行程名稱、地區、摘要、分類、天數、團期備註及已發布方案的航空、名稱、摘要、航班、住宿文字。空白分隔多個詞採全部符合，可和月份／預算合併。支援大小寫、全形字、台／臺正規化及少量共用目的地中英文別名；不需逐行程打標，不讀取 PDF 內文，不呼叫 AI。

驗證：59 個單元測試、lint、build 通過。Chrome 上方搜尋日本可找到本機 2 筆示意行程，下方改搜峇里島為 1 筆，兩組欄位同步；390px／320px 無整頁橫向溢出。尚未部署。

## 2026-09-16：不限條件結果與直接連結修正

依使用者新要求，跟團入口不再因舊版本缺少服務類型而將商品放入待確認區。前台統一直接列出所有可瀏覽的候選卡，只有整份候選清單為空才顯示無結果，no_results 事件同步修正。已知不符條件仍排除，沒有改成保證有位或保證符合所有偏好。

移除待確認區塊、條件確認徽章與逐項提醒。缺少的航班或住宿不再填入待確認字樣。每張卡與收藏卡都提供對應行程頁的版本錨點，以及原有 PDF／Drive 文件連結。系統產生的問答文案與詢問摘要已移除中文分號。

新增回歸測試：9 個已發布、具未來團期但沒有服務標籤的版本，在不限偏好時全部直接出現。60 個單元測試與 build 通過。此變更取代前文「獨立待確認區」設計，未部署。
