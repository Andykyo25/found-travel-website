## 決策摘要

先完成「旅行需求分流 → 規則挑選／比較 → 業務接手」，再試辦「我的旅程」。這兩段都不需要 AI API。先用流程與資料建立特色，AI 僅作為日後可關閉的文字整理工具。

- 起步 AI API 預算：NT$0／月。
- 有需求才啟用的小規模 AI 試辦：建議預留 NT$100～300／月，屬管理預算，不是固定月租或支出預測。
- 第一版不做全天候自由聊天、自動報價、剩餘團位承諾、語音客服、自架大型模型或模型訓練。
- 費用優先順序：沿用既有程式與欄位 → 表單與固定規則 → 業務確認的範本 → 少量 AI 請求。

## 哪些功能真的需要 AI API？

| 功能 | 第一版做法 | AI API 必要性 |
|---|---|---|
| 不同旅行形式的需求分流 | 分支表單 | 不需要 |
| 日期、預算與航空版本推薦 | 固定規則與已確認資料 | 不需要 |
| 顯示比較與符合原因 | 結構化欄位＋文字範本 | 不需要 |
| 需求摘要交給業務 | 把填答組合成摘要 | 不需要 |
| 我的旅程／進度／文件 | 授權後讀取訂單資料 | 不需要 |
| 截止日前待辦提醒 | 日期計算＋狀態判斷 | 不需要 |
| 任意自然語言理解 | 先用可選項＋補充文字人工處理 | 有價值時才加 |
| PDF 文字整理 | 能抽文字就先抽取，再由業務整理 | AI 是可選加速器 |
| 掃描 PDF 辨識 | 先測實際文件品質，必要時人工輸入 | OCR／視覺模型另外評估 |

網站與出團系統之間可能仍需要一般資料 API；「不用 AI API」不代表不用資料整合。

## API 費用如何計算

以下以 OpenAI 官方模型頁在 2026-09-10 查得的標準文字價格做可重算範例。不是所有供應商或模型中最低價的保證；正式啟用前仍需確認可用性、價格與任務品質。

| 估算模型 | 每 100 萬輸入 tokens | 每 100 萬輸出 tokens | 本計畫用途 |
|---|---:|---:|---|
| GPT-4.1 nano | US$0.10 | US$0.40 | 短需求分類／抽取的低成本測試基準 |
| GPT-4.1 mini | US$0.40 | US$1.60 | 較複雜文字整理的比較基準 |

來源：[GPT-4.1 nano 官方價格](https://developers.openai.com/api/docs/models/gpt-4.1-nano)、[GPT-4.1 mini 官方價格](https://developers.openai.com/api/docs/models/gpt-4.1-mini)。兩者官方頁皆說明無 reasoning step；若改用推理模型，要另計該模型實際計費用量。

Token 是模型處理文字的單位，不等於中文字數。輸入包含指令、客人文字、傳給模型的行程內容與對話歷史；輸出是生成內容。本表使用假設用量，正式上線後以實際 API 用量計算。

月模型費（美元）＝ Σ（每次輸入 tokens × 輸入單價＋每次計費輸出 tokens × 輸出單價）÷ 1,000,000。

換算台幣暫用 US$1＝NT$32，僅為預算假設，非當日匯率。未含稅、匯差、刷卡費、工具費、儲存及其他雲端費用。

### 情境 A：一次性短文字整理

假設每次請求平均輸入 3,000 tokens、輸出 600 tokens；不使用搜尋、圖片、付費檔案檢索，也不預計快取折扣。

| 每月 API 請求數 | nano 美元／台幣 | mini 美元／台幣 |
|---:|---:|---:|
| 100 | US$0.054／約 NT$1.73 | US$0.216／約 NT$6.91 |
| 1,000 | US$0.54／約 NT$17.28 | US$2.16／約 NT$69.12 |
| 5,000 | US$2.70／約 NT$86.40 | US$10.80／約 NT$345.60 |

例：mini 每月 1,000 次＝1,000 × (3,000 × 0.40＋600 × 1.60) ÷ 1,000,000＝US$2.16。

這是請求數，不是訪客數。288 筆歷史紀錄不能推算未來每月請求量。一次填表若呼叫兩次，就需計兩次；重試與評估請求也要計入。以 1,000 次為基礎另抓一倍用量緩衝，mini 約 NT$138，因此小規模試辦可先設 NT$100～300 管理預算。

### 情境 B：多輪聊天為何更容易增加成本

假設每月 1,000 位使用者、每人 5 次請求，每次平均輸入 6,000、輸出 1,000 tokens：

- nano：US$5／約 NT$160。
- mini：US$20／約 NT$640。

若人數、對話輪數或平均上下文翻倍，對應成本也增加；如果每輪重新帶入全部歷史，輸入還會逐輪增長。本計畫不把這種模式列為起步功能。

### 情境 C：後臺整理公開行程文字

假設每月 100 份文件，先抽出文字後，每份輸入 10,000、輸出 1,500 tokens，使用 mini：US$0.64／約 NT$20.48。

這只是「已抽取文字的單次整理」費用，不代表 PDF 辨識全包價；掃描、圖片、OCR、重試、儲存與人工核對另計。優先只處理新增／改版文件，結果保存後重用，不在每位旅客開頁時重做。

## 最低成本的月費安排

| 階段 | AI API 費 | 其他費用與工作 |
|---|---:|---|
| P0～P1 規則版 | NT$0 | 沿用既有主機；有開發、內容整理與維護成本 |
| P2 我的旅程 | NT$0 | 可能增加資料讀取、驗證、文件流量或通知費；先盤點現有方案，不承諾全部免費 |
| P3 少量 AI 試辦 | 預算 NT$100～300／月 | 是可控上限提案，非固定月租；實際依用量 |

整體月支出＝既有主機／儲存費＋新增身分驗證／通知／流量費＋AI 實際費用＋維護成本。本次未查看帳單，因此不估報網站總月費。

降低支出的實際方式：

- [ ] 表單能處理的問題不送 AI；只在按「協助整理」或遇到需理解的自由文字時呼叫。
- [ ] 推薦先由資料庫／程式篩選，只送少量候選摘要，不送全部商品或客戶歷史。
- [ ] 第一版不用付費網路搜尋、向量資料庫、AI 圖片／語音、模型訓練。
- [ ] 相同行程的公開摘要產生一次，確認後保存；私有客戶內容不能共用快取。
- [ ] 先限制在後臺，避免公開機器人流量與連續重試增加帳單。
- [ ] 只在品質不夠且測試有改善時更換模型；不自動升級成昂貴模型。
- [ ] 自架模型不列優先：即使無 API 單次費，仍有硬體、電力、部署與維護成本。
- [ ] 付費啟用前確認付款、額度與帳號權限；本文數字是消耗估算，不代表最低儲值或固定月租。
